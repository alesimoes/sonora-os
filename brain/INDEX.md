- [ADR-0011](decisions/ADR-0011-native-plugin-suite.md) — **Proposed.** The native plugin suite: standard LV2/VST3 plugins from one codebase (DPF behind our own `Processor` interface), hosted like any third-party plugin; only meters run in the engine, and moving a processor (the master chain first) into the engine is a gated amendment; neutral `common/dsp` + `plugins/native/<name>`, editors drawn by `sonora-ui`, a `dsp-engineer` role; measured quality bars, golden files and per-instance CPU classes at q128; physical models validated against SPICE, never against a commercial plugin; AI chooses parameters and DSP makes the sound, so ONNX Runtime runs only in `sonora-analyze`, while the amp captures run on our own RT-safe NAM-class kernels in the host; the mix assistant emits undoable model-operation plans, reverb/delay first; an optional Claude layer over features, never audio (owner to rule on network, cost and privacy); our own names, no trademarks or artist names; work order N0–N7.
- [ADR-0012](decisions/ADR-0012-plugin-hosting-m9.md) — **Accepted in part** (M9). Owner: O1 insert undo (default undoable), O2 editor keyboard focus. Ordered implementation checklist.
- [ADR-0014](decisions/ADR-0014-midi-model-and-realtime-path.md) — **Proposed.** MIDI (DAW 6): track kinds audio/MIDI/instrument; MIDI regions in `common/model` as windows onto shared, copy-on-write sequences stored inline, non-overlapping, in ticks at 960,000 per quarter; the frame-anchored tempo map kept, with one exact 128-bit integer frames↔ticks↔bars conversion (`MusicalMap`, `ui/qt` moves onto it) under bounds (bpm 1–1000, power-of-two meters, ≤ 384 kHz); session format v4, ports by name; MIDI ports in `contracts/backend` as fixed per-block `MidiBuffer` slots at frame offsets (this ADR is the ADR-0007 §6 amendment); plan carries MIDI as frames; endings never dropped (2,064 reserved of 4,096), trackers after the delay queue, chase slots retired by epoch; instruments as chains with an event area and a carry buffer for skipped submits, transport in the clock region (`contracts/plugin` layout 2, amends ADR-0012 §2/§7.1); takes stamped against the audio clock and written live as SMFs whose tick is a frame, sync-then-patch checkpoints; SMF interchange in `sonora-convert`; version numbers are the next free at landing; phases M-0 to M-7. Revised with the rt- and plugin-engineer reviews (#93). Owner: O1–O8.
- [ADR-0015](decisions/ADR-0015-midi-sequence-storage-at-scale.md) — **Proposed.** MIDI sequences at scale (ADR-0014 Unverified 6 measured over the caps): canonical 4-quarter chunks shared by undo (a drag ~17 KiB, not 800 KiB; ADR-0009 unchanged), one content-addressed binary `.msq` sidecar per sequence in `MIDI Sequences/` written tmp+rename before the session file, its syncs paced behind take checkpoints while recording (~6× smaller than inline JSON), the undo window's chunk table sent as a Snapshot in ≤ 16 MiB parts (protocol bump), a 2^24-entry budget that evicts undo first and refuses at open, never while recording, automatic cleanup of unreferenced sequence files; lands as M-1c before M-3. Owner: O1–O5.
- [ADR-0016](decisions/ADR-0016-loop-record-take-model.md) — **Proposed.** Loop record: one take file per track written through the wraps, each wrap an in-band `CaptureBoundary::Wrap`; each pass a region of that file (handles for loop-end crossfades) on its own new playlist, the last complete pass on the active one; one `RecordLoopTake` per track so a Compound stays at T members; bext `loop=<A>-<B>`; wraps persisted in a sidecar at each checkpoint, so recovery and a full boundary ring still place every pass; loop plus punch refused, loop range frozen while recording. Revised with the architect's C1–C7 (#114). Owner: O1–O3.
- [ADR-0018](decisions/ADR-0018-session-folder-owns-its-media.md) — **Proposed.** The session folder owns its media: the engine records takes, flushes plugin state and reads sources in one active session folder, changed only on the control thread while no take is open or closing; `Load` carries the session file's path (protocol bump), and Load is refused during a take; a new session gets a visible `Untitled <n>` folder that the first Save renames; Save As hard-links on one volume and copies durably across volumes, never references outside the folder; recovery and the orphan offer run per folder (#132's name filter goes); existing sessions get an explicit gather from the old shared folder; free space and read-only media are refused at take start; preallocation waits for a measurement; session format unchanged. Owner: O1–O3.
- [ADR-0019](decisions/ADR-0019-round-trip-latency-loopback.md) — **Accepted.** The round trip L (out, back in, converters included) measured by an impulse probe that runs at the end of `Session::process()` through SPSC rings, on a spare output cabled to a spare input; a plain or punched take captures its timeline range L frames later on the playhead and labels its files P0 − L, so placement needs no latency arithmetic; loop takes keep ADR-0016's wrap arithmetic with the session's L; monitored input is not moved by L, only by the plan's PDC like playback; L set or measured at engine start (`--input-latency`, `--measure-latency`), refused during a take; drivers/fake cables an output to a capture port so CI measures it. No contract change.
- [ADR-0021](decisions/ADR-0021-crossfade-placement-on-short-handles.md) — **Accepted.** Crossfades join butted regions only (placement trims, the trimmed audio is the handle); the selection picks pre, post or centred; on short handles the Edit-window gesture shortens the crossfade to the audio there is, keeping the placement, a centred one with no audio on one side moving to the other as pre or post, refused only with nothing to draw on (`model::fit_crossfade`, `crossfade_handles`); the model still refuses any crossfade past a handle (ADR-0009). Equal power by default, linear for correlated material. No format or protocol change.
- [ADR-0022](decisions/ADR-0022-sends-and-aux-buses.md) — **Accepted.** Sends onto aux buses, a stereo bus and its return strip as one object returned to the monitor bus (the least of `ui.mixer.io` sends need); 10 send slots A-J per track and per bus; structure undoable, levels/pans/mutes/pre-post mix state; feedback loops refused at the model and by `check_invariants`; a send is a plan edge from the strip's pre-fader node into an `AuxSum`, ramped per callback, pre-fader silenced by the strip's mute; fixed summing order; PDC over the larger graph. Session format 11, protocol 27, `PlaybackConfig::max_buses` 32.
- [ADR-0023](decisions/ADR-0023-track-structure-operations.md) — **Accepted.** Track structure: `RemoveTrack` and `DuplicateTrack` as operations of their own (a compound would hit the 256-member limit); a duplicate is a new track below its source with fresh ids in a fixed order, the active playlist, inserts, sends and mix copied (solo off), sources and MIDI sequences shared; a delete keeps the mix, insert and send values for undo. Engine tracks stay positional: a plan built after a change of track order carries each engine track's fader, pan, mute, solo, monitor, arm, input and send slots, used until the atomics are written once no block can be on the old plan. While a take starts or closes nothing changes the tracks; while one records, armed rows are pinned. Session format 11 unchanged, protocol 28. Update 2026-11-02: a palette colour stored on every track and on a region that has its own (`SetTrackColour`, `SetRegionName`, `SetRegionColour`), so a moved track keeps its colour; session format 15, protocol 38.

- [ADR-0027](decisions/ADR-0027-automation-lanes-and-modes.md) — **Accepted** (recommended defaults). Automation: per-parameter breakpoint lanes on `TrackEdit`, undoable through one `EditAutomation` (range replace); the mode (off/read/touch/latch/write/trim) is saved, non-undoable mix state; the plan carries lanes immutably and the audio thread evaluates them statelessly on a 32-frame timeline grid (block-split invariant), crossfading one callback on a discontinuity; live writes through atomics and a fixed ring, one undo step per pass; plugin lanes at block rate into ADR-0012's last-value table. - [ADR-0024](decisions/ADR-0024-buses-paths-and-output-routing.md) — **Accepted.** Output routing: every track and aux return has one output, the Master (the monitor bus, never deleted) or an aux bus; `SetOutput` is an undo step; sends and outputs form one acyclic bus graph, a loop refused naming the path; aux solo (`BusMix::solo`) solos what feeds the aux through any buses, computed on the audio thread from the playing plan; a strip's last node feeds its output's `AuxSum`, PDC unchanged. - [ADR-0026](decisions/ADR-0026-playlists-per-track.md) — **Accepted.** Playlists per track: `DuplicatePlaylist`, `SetPlaylistName` and `RemovePlaylist` join `AddPlaylist` and `SetActivePlaylist`, each Pro Tools command one undo step; names `<track>.<nn>`, unique in the session; a switch is a plan swap, exact at a block edge, nothing new in `process()`; no switch while a take starts or closes, nor on an armed track while it records, by op, undo or redo; media any playlist (or a removed one) references stays in the pool, never orphaned. - [ADR-0017](decisions/ADR-0017-windows-plugins-through-yabridge.md) — **Proposed.** Windows plugins through yabridge 5.1.1 (GPL-3, pinned) on Debian's Wine 10.0, bridged VST3 only, no new path. Measured in a container: scan, probe, run, crash isolation; a buffer-overrunning plugin is refused by the timeout rather than the trap; yabridge adds ~100 µs p50, ~350 µs p99 per chain. VST2, CLAP, appliance packaging and the catalog field are deferred.
- [ADR-0029](decisions/ADR-0029-plugin-presets-and-state-files.md) — **Accepted** (recommended defaults). Seven slices; five items unverified.

## Research
- [Disk write path](research/disk-write-path.md) — the disk thread keeps unbuffered stdio through the page cache and its 10 ms poll. O_DIRECT stalls each write (p99 9–20 ms against under 1 ms), uses 2–3 times the CPU at 18 tracks, and loses up to 4 KiB per track to kill -9. A signalled wake puts a `sem_post`, a system call, in every callback (35–44 µs median) to save 10 ms of a 4 s ring. Measured on WSL2; the USB stick and SSD are unverified.
- [CI compiles with the shipped toolchain](research/ci-shipped-toolchain.md) — every CI job that compiles C++ does so in a trixie image (GCC 14, baseline x86-64; clang-22 for RTSan) on a pinned `ubuntu-24.04` runner and prints its compiler; `ubuntu-latest` had moved to Ubuntu 26.04's x86-64-v3 GCC 15 unnoticed (#154).
- [Multichannel USB interfaces](research/multichannel-usb-interfaces.md) — Pro Audio profile, WirePlumber state hooks, port ordering; what is verified and what is not.
- [ADR-0007 measurements](research/adr-0007-measurements.md): the six "Unverified" items. RTSan is available (`clang-22` in trixie main; the default clang 19 lacks it). 8-byte atomics are lock-free on amd64 and arm64. Container IPC figures: socket and seqlock costs are fine, but a seqlock publisher must be paced and spinning at FIFO hits RT throttling. `snd-dummy model=rme9652` gives 26 ordered AUX ports in QEMU. cage maximizes parentless X11 editors.
- [Pro Tools and Logic key bindings](research/protools-logic-key-bindings.md) — every binding in both profiles checked against Avid's and Apple's own guides; corrections, collisions, the Commands Keyboard Focus problem, and what the schema cannot express.
- [Pro Tools workflow parity audit, 2026-11](research/protools-parity-audit-2026-11.md) — first-hour tracking workflow against Pro Tools: status per step, ranked, top 15 BACKLOG lines
- [Qt shell render cost](research/qt-shell-render-cost.md) — 18 meters at 60 Hz on llvmpipe only: about one core, 0.04 ms GUI tick; no GPU figure yet; the software scene graph cannot draw the meters at all.
- [USB stick layout](research/usb-stick-layout.md) — the ISO's MBR already has the ESP as partition 2, so persistence is 3; parted cannot edit it; the overlay lives in `home/rw`; `systemd.run=` needs `systemd.unit=` on this image.
- [BWF interop](research/bwf-interop.md) — takes checked with ffprobe, soxi, libsndfile, mediainfo and headless Ardour 8.12 (`tools/test-bwf-interop.sh`, CI job `interop`). All 36 files open as 24-bit 48 kHz at the right length, and Ardour places each at its TimeReference, including a non-zero take 2. Defect: OriginationDate/Time empty. Ardour treats TimeReference 0 as no timestamp. The writer wraps sizes past 4 GB instead of stopping.
- [Native plugin suite](research/native-plugin-suite.md) — literature, not measurement: published technique, parameters, oversampling, estimated cost class and validation for each first-party plugin (EQ to mastering, opto/FET levellers from public schematics, tube/transformer/tape, amps and cabs); BS.1770-5 true-peak is 4x at 48 kHz; AI parts (mastering analysis, timbre match, tuner, mix assistant, reverb/delay suggestions) are analysis-time except neural amp models and DSP pitch tracking; licence tables for code and datasets (RAVE, DeepAFx-ST, Diff-MST, madmom/Essentia models, MedleyDB, MUSDB18, Open-Unmix weights are non-commercial: excluded; CREPE weights trained on MedleyDB-derived data); legal notes.
- [Modelled noise and hum, N2 slice 5](research/native-noise-hum-n2.md) — the tube stage's thermal and shot noise (Req = 2.5/gm) and a bridge supply's ripple, each held to ngspice on the same circuit (noise density 1.5e-6 dB, ripple 0.0006 dB, transfer 7e-8 dB); the processor's noise within 0.41 dB per third-octave band and hum within 0.0002 dB; contributions at 100 %, drive 0 dB: noise -108.3 dBFS, hum -121.7 dBFS (50 Hz); +2 us a block on eco; flicker noise and heater hum not modelled (no citable figure).
- [Open data and DSP sources](research/open-data-and-dsp-sources.md). A licence survey, read from the sources on 2026-10-13. Nothing was downloaded or run.
  - **Shippable (CC BY 4.0):** VocalSet, vocadito, GuitarSet, Dagstuhl ChoirSet, EGFxSet, SignalTrain, VCTK, Arni and Motus RIRs.
  - **Non-commercial:** MUSDB18-HQ, MoisesDB, MedleyDB, MTG-Jamendo, IDMT-SMT-Guitar, MDB-stem-synth, EARS and GTSinger.
  - **Excluded as unclear:** NUS-48E, MIR-1K, EGDB and the MIT IR Survey.
  - **Captures and IRs:** TONE3000 captures are not redistributable (T3K licence). No cabinet IR set has a licence we could verify.
  - **Weights:** Spleeter's are MIT by Deezer's own statement, and it is the least-bad separation model. Demucs, Open-Unmix, CREPE, SwiftF0, PESTO and Basic Pitch weights rest on non-commercial or unclear data.
  - **Open question:** Slakh and StemGMD are MIDI rendered through commercial instruments; it is open whether ADR-0011 §4.6 excludes them.
  - **Code:** a licence table for about 40 DSP projects and about 35 neural-DSP repositories.
  - **Amps, speakers, mics:** a "virtual capture" pipeline (SPICE of published circuits plus maker T/S curves) with its limits and validation plan; mic modelling; vocal-balancing data. Biggest gap: no commercially licensed multitrack corpus.
- [VST3 in the plugin host](research/plugin-host-vst3.md) — VST3 SDK licence checked at the source (MIT since 3.8, 2025-10-29; Debian's 3.7.10 headers used under GPL-3: compatible). AGain gain exact, LSP limiter latency matches measured to the sample, also in a mixed LV2+VST3 chain and across a runtime look-ahead change (reported 35 ms late); crash, bus-mismatch and 8-channel liar refused. `getLatencySamples()` at activation was 0 for a 240-sample plugin.
- [LV2 plugin host, container](research/plugin-host-lv2-container.md) — `sonora-plugin-host` with eg-amp, x42-dpl and the LSP limiter: gain exact, reported latency matches measured to the sample and PDC nulls to 0, a segfaulting plugin kills only the host and is named, a late one is dropped then removed; round trip p50 62 µs / p99 252 µs (container). A timed wait overshot 2 ms by 5.9 ms once: argues for pipeline depth 1.
